# umulaunch

Небольшой GUI-лаунчер для Linux (чистый Wayland, [iced](https://github.com/iced-rs/iced)),
который запускает Windows-игры через [umu-launcher](https://github.com/ValveSoftware/umu-launcher):
`umu-run <PlayGame.exe>` с правильными `GAMEID`, `STORE`, `WINEPREFIX`, `PROTONPATH`.

Никакой своей прослойки совместимости — umu-launcher остаётся единственном месте,
где решается, какой Proton и какие префиксы использовать. Лаунчер только хранит
библиотеку игр и подставляет нужные переменные, а если подходящего Proton в системе нет —
умеет скачать нужную версию GE-Proton, проверить контрольную сумму и положить её туда,
где её увидят Steam, Lutris и сам лаунчер (см. «Загрузка Proton»).

```
┌ umulaunch ─────────────────────────────────────────────────────────┐
│ ▶ umulaunch [umu-run]   [Proton] [перечитать] [сохранить] [новая]  │
├─ по умолчанию ─────────────────────────────────────────────────────┤
│ раннер · STORE · umu-run · префиксы · папки раннеров   [свернуть]  │
├─ Игры                       ┬─ Карточка игры                       ┤
│ ● <имя игры>    [авто] [▶]  │ <имя игры>     [готова к запуску]    │
│ ▎○ <вторая игра>[авто]  [▶] │ [▶ запустить] [править]   [удалить]  │
│ фильтр…            [2 игр]  │ путь [обзор] · префикс [обзор]       │
│ папка Steam [обзор] [найти] │ аргументы · раннер · переменные      │
│                             │ команда запуска (= --dry-run)        │
│                             │ хвост лога игры                      │
└─ umu-run · игр · запущено   ┴─ Ctrl+S · Ctrl+R · Ctrl+Q · Esc      ┘
```

## Установка

### NixOS (модуль из flake)

```nix
# flake.nix вашей системы
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    umulaunch.url = "github:ВАШ/umulaunch";
  };

  outputs = { nixpkgs, umulaunch, ... }: {
    nixosConfigurations.ИМЯ = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./configuration.nix
        umulaunch.nixosModules.default
      ];
    };
  };
}
```

`nixosModules.default` просто добавляет пакет в `environment.systemPackages`.
Обёртка бинарника кладёт `umu-launcher` в `PATH` и все dlopen-библиотеки
(`libGL`, `vulkan-loader`, `libxkbcommon`, Wayland) в `LD_LIBRARY_PATH`, поэтому
`umu-run` ставить отдельно не нужно. В меню приложений появляется ярлык
`umulaunch.desktop` (`share/applications`).

Пакет также можно поставить в профиле пользователя:

```bash
nix profile install github:ВАШ/umulaunch
```

### Непакетная сборка

```bash
cargo build --release      # нужен pkg-config и системные библиотеки Wayland/Vulkan
```

На NixOS для этой сборки есть `nix develop` (пути `LD_LIBRARY_PATH` уже проставлены).

### Как это выглядит в nixpkgs

Упаковка лежит в [`nix/package.nix`](nix/package.nix) и написана в стиле
`callPackage`, так что для подачи upstream достаточно заменить `src` на
`fetchFromGitHub`:

```nix
# pkgs/by-name/um/umulaunch/package.nix
{ lib, fetchFromGitHub, ... }:
rustPlatform.buildRustPackage rec {
  pname = "umulaunch";
  version = "0.1.0";
  src = fetchFromGitHub {
    owner = "ВАШ";
    repo = "umulaunch";
    rev = "v${version}";
    hash = "sha256-…";
  };
  cargoHash = "sha256-…";
  ...
}
```

## Конфиг

Файл ищется в порядке:

1. `$UMULAUNCH_CONFIG` (переменная окружения, полный путь к TOML);
2. `$XDG_CONFIG_HOME/umulaunch/config.toml` (обычно `~/.config/umulaunch/config.toml`);
3. `$XDG_CONFIG_HOME/umulaunch/games.toml` — старое имя, читается, если нового нет.

Логи игр: `$XDG_STATE_HOME/umulaunch/<имя-игры>.log`.

Значение `~` разворачивается в `$HOME` в любом пути, так что конфиг переносим между
машинами и не привязан к одному пользователю.

```toml
# umu-run по умолчанию ищется в PATH и в типовых местах; указать вручную:
# umu_run = "~/bin/umu-run"

[defaults]
# runner = "<каталог Proton>"   # пусто — решает umu-launcher
store = "none"                  # none | heroic | gog | epicgames | legendary | other
prefix_root = "~/Games/umu"     # префиксы вида <prefix_root>/<GAMEID>
# runner_dirs = ["~/proton"]    # где ещё искать раннеры, кроме типовых мест

[[game]]
name = "<имя игры>"             # обязательно; от него зависят GAMEID и имя файла лога
exe = "~/Games/<иг>/<launcher>.exe"   # обязательно; ~ разворачивается

# остальное необязательное — берётся из [defaults]
# gameid = "steam-<AppID>"      # по нему umu подбирает правки для игры;
#                               # пусто — слаг из имени
# prefix = "~/Games/umu/<GAMEID>"
# store = "gog"
# runner = "~/proton/<сборка>"
# args = ["<аргумент>", "<ещё>"]
# [game.env]
# DXVK_HUD = "compiler"
```

`[[game]]` — поле `name` обязательно, `exe` — обязательно; пустой конфиг не ошибка,
просто список игр пустой (кнопка «новая игра» добавляет первую).

## Что делает запуск

Для каждой игры собирается одна команда — карточка игры и `--dry-run` печатают её
целиком, в кавычках, так что строку можно вставить в терминал:

```
cd '<каталог exe>' && WINEPREFIX=<префикс> GAMEID=<gameid или слаг имени> \
  STORE=<store> PROTONPATH=<раннер> UMU_LOG=1 <env из конфига> \
  umu-run '<путь к exe>' [args…]
```

Плюс, если путь к `.exe` лежит внутри `…/steamapps/common/…`, добавляются
`STEAM_COMPAT_INSTALL_PATH` и `STEAM_COMPAT_LIBRARY_PATHS`. Без них Proton, который
запускает не Steam, не заводит игре буквенный диск, и игра падает на старте; с ними
поведение совпадает с Lutris/Steam. Кнопка запуска и `--dry-run` показывают итоговую
команду целиком, так что любой запуск воспроизводится из терминала.

## Раннеры

Список для выбора строится автоматически: каталог считается раннером, если внутри
лежит исполняемый файл `proton`. Ищется в

- `$XDG_DATA_HOME/Steam/compatibilitytools.d`
- `~/.steam/steam/compatibilitytools.d`, `~/.steam/debian-installation/compatibilitytools.d`
- `$XDG_DATA_HOME/lutris/runners/proton`
- `$XDG_DATA_HOME/heroic/tools/proton`
- `$XDG_DATA_HOME/umu`, `/opt/umu/runners`
- каталогах PortProton: `$XDG_DATA_HOME/PortProton`, `~/.local/share/portproton`,
  `~/.cache/portproton`, `/opt/PortProton` и внутри flatpak-версии
  (`~/.var/app/ru.linux_gaming.PortProton/data/PortProton`)
- `compatibilitytools.d` flatpak-сборок Steam и Lutris
- `steamapps/common` всех Steam-библиотек — и здесь уже подходят только каталоги с
  `proton` в имени, чтобы десятки игр не превращались в «раннеры»

Библиотеки Steam берутся из `libraryfolders.vdf` (там лежат второй и последующие
диски), поэтому Proton с отдельного диска находится без ручных настроек. Плюс
`defaults.runner_dirs` из конфига — он не заменяет поиск, а добавляется к нему.

Дубликаты схлопываются по настоящему пути (Steam-каталог обычно виден и по
`~/.local/share/Steam`, и по `~/.steam/steam`), поэтому один и тот же раннер не
плодит три одинаковые строки. Первый пункт списка — «авто»: раннер не передаётся, и решает
umu-launcher (обычно это `proton-ge` или `wine-ge` из своих кэшей).

## Выбор пути (обзор)

Рукой пути вводить не нужно: у поля `.exe`, у `wine-префикса`, у `umu-run`, у корня
префиксов, у дополнительных папок раннеров и у папки Steam-библиотеки есть кнопка
`обзор`. Она открывает список в правой панели: сначала папки (скрытые точкой — в
конце), для `.exe` и `umu-run` ещё и файлы; сверху — текущий путь, `↑ вверх`,
`отмена`, фильтр по имени и `выбрать эту папку`. Скрытые каталоги не уезжают за
первый экран, длинный список ограничивается 400 записями с подсказкой «уточните
фильтром». `Esc` закрывает обзор, карточка игры при этом остаётся открытой.

## Загрузка Proton

Кнопка `Proton: загрузки` в шапке открывает панель со списком релизов
[GE-Proton](https://github.com/GloriousEggroll/proton-ge-custom) (берётся с GitHub API,
нужна сеть). Тег выбирается из `pick_list`, справа видны размер архива, дата публикации
и способ проверки. Скачанный релиз кладётся в `$XDG_DATA_HOME/Steam/compatibilitytools.d`
(обычно `~/.local/share/Steam/compatibilitytools.d`) — это первый каталог из поиска
раннеров выше, поэтому сразу после установки новая версия появляется во всех списках
раннеров: в карточке игры, в `defaults.runner` и в «раннер по умолчанию».

Что происходит при установке:

- архив (~500 MiB) скачивается в временный файл, хеш считается по потоку во время
  загрузки — файл не перечитывается второй раз;
- контрольная сумма сверяется до распаковки. GE-Proton публикует `<tag>-x86_64.sha512sum`,
  поэтому алгоритм берётся из имени файла суммы (`sha512sum`/`sha256sum`/`.sum`);
  если релиз сумму не публикует (такое бывает со старыми версиями), панель честно
  предупреждает и ставит как есть;
- до начала загрузки проверяется, что целевой каталог свободен с трёхкратным запасом,
  а такого раннера там ещё нет;
- распаковка идёт в `<каталог>/.umulaunch-<ТЕГ>` и только потом переименовывается в
  итоговое имя, так что полускачанный или побитый Proton не может стать раннером.
  Пути внутри архива проверяются: абсолютные пути и `..`, уводящие наружу, отвергаются,
  как и симлинки, указывающие за пределы каталога установки;
- кнопка «прервать» выставляет флаг отмены; рабочий поток договаривает текущий блок,
  удаляет скачанный архив и временный каталог, поэтому отменённая установка не оставляет
  мусора и недособранного раннера.

Список строится запросами к API по 100 релизов, максимум 5 страниц — этого хватает на
несколько лет веток GE-Proton. Без токена GitHub лимит — 60 обращений в час на IP: при
исчерпании панель сообщает, что лимит кончился, и предлагает попробовать позже.

Имя каталога берётся из структуры архива: если внутри одна папка — она и есть имя
(GE-Proton раскладывается в `GE-Proton11-11-x86_64`), если файлы лежат сразу — каталог
называется по тегу релиза. Отметка «уже установлен» и проверка перед скачиванием ищут
каталог по тегу с границей имени, поэтому и `GE-Proton11-11`, и
`GE-Proton11-11-x86_64`, и старый `Proton-<ТЕГ>` считаются установленными — лаунчер не
будет второй раз качать 500 MiB ради уже имеющегося раннера.

## Библиотека игр

- фильтр по имени и по пути к `.exe`; кнопка `✕` очищает фильтр, плашка рядом
  показывает «N игр» или «X из Y», когда фильтр что-то отсеял;
- карточка «по умолчанию» сворачивается: развёрнута она при пустой библиотеке,
  свёрнута — когда игры уже есть, чтобы список и карточка занимали всё окно.
  В свёрнутом виде остаётся одна строка с тем, что сейчас действует;
- «новая игра» и редактирование карточкой справа: что даст имя (GAMEID, префикс,
  файл лога) видно прямо под полем;
- удаление с подтверждением вторым нажатием — запущенную игру сначала останавливают;
- «сохранить» пишет конфиг атомарно, через временный файл; закрытие окна тоже
  сохраняет — сначала запись, потом выход, так что забытый Ctrl+S не стоит
  потерянной библиотеки. Не удалось записать — текст ошибки уходит в терминал,
  окно при этом закрывается (дальше молчать было бы хуже);
- в форме игры выбор раннера идёт после аргументов запуска: сначала путь и параметры,
  потом уже «чем запускать»;
- скан Steam-библиотеки: укажите каталог, лаунчер найдёт `*/steamapps/common/*`,
  подберёт главный `.exe` и добавит игры разом, пропуская уже известные;
- «остановить» гасит всё дерево процессов (`umu-run` → `proton` → `wine`), а не только
  прямого ребёнка, иначе игра остаётся висеть в фоне;
- в строке игры: точка статуса, путь к `.exe`, раннер и кнопка запуска — играть
  можно, не выбирая её; у запущенной там же время работы и pid, у завершённой —
  код выхода;
- в карточке выбранной игры: плашка «готова к запуску» (или причина, почему не
  готова), путь, раннер, префикс, `GAMEID · STORE`, аргументы, окружение, команда
  запуска — та же строка, что печатает `--dry-run`, — и кнопки действий сразу под
  заголовком;
- хвост лога выбранной игры и путь к файлу лога; ответы действий (ошибка,
  предупреждение, «готово») показываются баннером внизу окна, а не молчаливой
  строкой; внизу же — счётчики игр, запущенных процессов и найденных раннеров.

Комментарии в конфиге не переживают «сохранить»: файл перегенерируется из структуры
данных. Если нужны комментарии, правьте секции руками — лаунчер перечитает их по
Ctrl+R.

## Терминал

```bash
umulaunch --help              # флаги и схема конфига
umulaunch --version           # версия
umulaunch --list              # что видно в конфиге и как разворачиваются значения
umulaunch --runners           # найденные раннеры
umulaunch --dry-run "<имя>"   # команда запуска, ничего не стартует
umulaunch --launch "<имя>"    # запустить и ждать выхода (для скриптов)
umulaunch --proton-list       # доступные GE-Proton (нужна сеть)
umulaunch --proton-install "<ТЕГ>"   # скачать, сверить хеш, установить
```

Имя игры можно задавать частично: хватит подстроки, точное совпадение приоритетнее.
`--launch` печатает ту же команду, что `--dry-run`, и завершается кодом выхода
игры — им удобно пользоваться из скриптов. `--proton-list` и `--proton-install` —
то же, что делает панель загрузки, но без окна; конфиг при этом не читается, так что
поставить раннер можно и с сломанным `config.toml`. Прогресс установки печатается в
stderr одной перезаписываемой строкой, итог — в stdout, так что вызов удобно оборачивать
в скрипт. Коды возврата: 0 — успех, 1 — ошибка конфига, сети или запуска, 2 — неверный
вызов (незнакомый флаг, имя игры или тег без аргумента).
Эти режимы не открывают окно, поэтому удобны для проверки упаковки и для
`--check`-сборок.

В окне работают Ctrl+S (сохранить), Ctrl+R (перечитать конфиг), Ctrl+Q (сохранить и
выйти — тот же путь, что у крестика окна) и Esc (закрыть обзор пути, карточку
редактирования или панель загрузки Proton).

## Разработка

```bash
nix develop                                  # cargo/rustc + пути для dlopen
cargo run                                    # GUI прямо из дерева
cargo test                                   # конфиг, слаг, аргументы, кавычки, дерево процессов
nix build .#umulaunch && ./result/bin/umulaunch   # проверка готовой обёртки
nix fmt flake.nix nix/package.nix
```

После изменения зависимостей в `Cargo.toml` нужен новый `cargoHash`: поставьте
заглушку `sha256-AAAA…=` и прочитайте строку `got:` в сообщении о несовпадении.

## Зависимости

Во время сборки: `pkg-config`, библиотеки-разработки alsa/fontconfig/wayland, а из
crate-зависимостей — `iced`, `serde`/`toml`, `dirs`, `libc` и стек загрузки
(`ureq` с корнями webpki — системные CA не нужны, что для NixOS важно — `serde_json`,
`flate2`, `tar`, `sha2`, `tokio` для фоновых задач).
Во время работы: `libGL`/`vulkan-loader`/`libxkbcommon` (окно), X11-клиентские
`libX11`/`libXcursor`/`libXi`/`libXrandr`/`libXfixes`/`libXrender` — их winit грузит
через `dlopen`, и без них окно не появится в иксовой сессии или под XWayland,
`umu-run` из `umu-launcher` (собственно запуск). Nix-обёртка закрывает и то, и другое.
Панель загрузки Proton и `--proton-*` дополнительно требуют доступа к
`github.com:443` — больше наружу лаунчер не ходит.
